# V3：年份确认与生活化偏好多轮验证

同一本地 `qwen3:4b` 模型，非思考模式；不修改 V1/V2。**先看 [实测结论与待修问题](RESULTS.md)。**

## 这次实现了什么

- 固定注入客户端参考日期 `2026-10-16` 和时区 `America/Los_Angeles`，不读取执行机器日期来推断年份。
- 没有年份的月日：代码提出当前年或下一个有效日期，确认前 `start_date=null`。今年已过则说明；闰日寻找有效年份。
- 明确“回顾”过去行程时，使用过去方向的候选，并保留 review 意图；该意图识别目前只使用有限词语，不能处理所有否定。
- 同时只保留一个当前追问；精确“是的”“2027年”和选项编号/标签通过代码绑定，不额外调用模型。
- 模型只提取当前消息的原文；跨轮字段记忆、日期确认、选项文案由代码管理。因此本实验不是端到端 LLM 多轮推理能力评测。
- 用户可以自由描述节奏；也可选择“轻松玩 / 适中 / 多看一些 / 还没想好”。默认适中必须标明 assumption，不作为用户已经明确选择。
- walking_load、drive_pace、early_start、lodging_changes 分开保存，老人同行不会自动选择轻松节奏。
- 程序产生实际追问文本，记录每轮输入、原始模型输出、状态变化、预期和差异；尚未接入网页或行程引擎。

## 复测

先按上一级 README 启动本机 Ollama，再在此目录运行：

```powershell
python -m unittest -v test_dialogue
python run.py

# 额外边界探查：不调用模型；当前 3 项已知失败，只打印结果，不混入主实验分数
python exploratory_probes.py
```

每次 `run.py` 创建新的 `runs/<UTC运行ID>/`，不会覆盖历史报告。修改冻结文件会被拒绝；下一次修复应另建版本。

## 文件

- `dialogue.py`：原文证据、对话状态、年份确认、偏好标准化、追问模板和选项。
- `prompt.txt`：当前轮原文提取规则。
- `scenarios.json`：18 组预先脚本化对话，共 36 轮，含人工 gold 提取和逐轮断言。
- `test_dialogue.py`：6 个代码测试，其中含全部 18 组 gold 对话子测试，以及时钟注入、拒绝后不默认确认、伪造证据等基础检查。
- `frozen-manifest.json`：主实验推理前固定的案例、提示词与代码摘要，也固定所依赖的 V2 intake 文件。
- `runs/.../TRANSCRIPTS.md`：真实每轮输入与回复，失败优先。
- `runs/.../report.json`、`turns.jsonl`、`metadata.json`：完整模型调用和状态记录。
- `EXPLORATORY_PROBES.json`：主实验后额外发现的代码边界失败，使用预设正确提取，不是模型输出。

## 评分边界

- 主实验：每轮对预先指定的关键状态和问题做断言，整组所有轮都通过才算场景通过。没有断言的字段不等于全部正确。
- 原文标注覆盖是辅助指标，可能因引用长度等差异偏严格；不能代替语义正确性。
- 脚本化用户回复不会因为程序问错而改变，因此比真人对话更简单；失败后继续的后续轮不能视为真实用户已经顺利完成。
- 额外 3 个边界检查在主实验后添加，分开报告，不修改主实验分数，不冒充推理前冻结集。
- 实现和测试由同一作者编写，不是独立盲测。新任务与 V2 的单轮评分不同，不能比较百分比后宣称模型能力提高。
- 当前没有完整自然语言纠错、撤销、任意选项指代和日期分量合并；已复现的问题见 RESULTS。原型不能直接作为可靠线上对话入口。
