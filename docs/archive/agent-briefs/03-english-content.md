# 任务：给一组数据写英文版（按英语母语的写法写，不是翻译）

项目在 `D:\LLM\Team`，是一个美国国家公园行程规划网站，原来只有中文。我们在加英文版 `/en`，给英语母语的读者用，会拿去做课程展示，**英文质量要像美国资深国家公园作者从头写的**。

## 先读这些

1. **`D:\LLM\Team\docs\ENGLISH.md`**：写法规范，包括语气、事实、地名、英制单位、日期时间、本地化、术语表。必须逐条遵守。
2. 每组对应的中文数据源文件（见下面），用来看清每段中文是什么字段、在讲哪个景点：
   - `D:\LLM\Team\src\data\attractions\<公园代码>.ts`：景点。`nameZh` 是名字，`summary` 是 1–3 句介绍，`tips` 是实用提示，`closedNote` 是不开放时的说明，`permit` 是许可证说明，`start.nameZh` 是停车或出发点的名字（短标签）。字段说明见 `src\data\attractions\types.ts`。
   - `D:\LLM\Team\src\data\suitability\<公园代码>.ts`：同行适合度。`noteZh` 写带小孩、老人、轮椅去要注意什么、怎么玩更稳妥。
   - 公园代码对应的公园名见 `src\data\parks.ts`。

## 要做的

你负责的每一组，都有一个文件 `D:\LLM\Team\src\i18n\en\content\attractions-<公园代码>.ts`。文件内容是 JSON 对象：键是中文原文，值是英文，空字符串表示还没写。

- **把每个空字符串都写成英文。** 键一个字都不能改，也不能删条目、加条目。
- **已经预填的值也要看**（多数是景点的官方英文名 `nameEn`）。一般保留不动；只有明显不对时才改，比如中文名对应的是停车场，但预填的却是步道名。
- 值是 JSON 字符串：英文里要用直的双引号就写成 `\"`，或者直接用弯引号 “ ”。不要加最后一个逗号，文件必须还能当 JSON 解析。
- 只改分配给你的这几个文件，别的文件都不要动。不要动 git，不要运行 `npm run i18n:en`（会和别人冲突）。
- 不用浏览器面板。一般不需要上网；只有拿不准官方英文名时，才用 WebSearch 或 WebFetch 查 NPS 官网。

## 写的时候特别注意

- **同一个景点的名字要处处一致**，跟名字条目（`nameZh` 那条）用同一个英文名。
- **单位换成英制**。景点数据里的 `hike.distanceMi`、`hike.gainFt` 是英里和英尺，直接用；中文里写"公里""米"的要换算，四舍五入规则见 ENGLISH.md。
- **短标签就写短**：`start.nameZh` 这类名字是标签，不要写成句子，比如 "Watchman trailhead by the visitor center"。
- **中文里专门写给华人看的内容按 ENGLISH.md 的本地化一节改写**，比如中国护照、亚洲超市、中文信息这类。
- **事实一个都不能丢**：日期、价格、规定、时间、年份、来源里提到的机构都要保留。中文本身矛盾或像是写错了的，照写，并在回报里列出来。
- 同一段中文会在多个景点出现时，只有一个条目，写成在各处都通用的说法。
