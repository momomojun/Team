# 11-25：说“带沙漠的国家公园”这一类公园，去查着推荐（分支 `fix/park-kind-ask`）

- 为什么做：v0.7.1 上线以后仓库主人在线上试（5 轮）：“我要去加州的国家公园玩”→“这个季节有什么推荐的”→“那我要去带沙漠的国家公园”→“有沙漠的国家公园”→“你给我推荐有沙漠的国家公园先，这个季节”。第 3、4 句 Gemini 的调度员当成给条件（conditions），这句里又没有公园名字，只会再问一遍“想去哪座”，说到第 5 句点明“推荐”才去查。线上日志（`/stats` 的 recent）能看到这 5 轮的结果和耗时。
- 做了什么：`pipeline.py` 加了 `PARK_KIND`：说的是一类公园（“带 / 有 / 能看到……的国家公园”，沙漠、海边、雪山、冰川、火山、峡谷、星空、红叶……的公园，英文 parks with……、desert / beach / mountain parks……）、没点名哪座、也不是在说州和片区（“加州的国家公园”照旧按片区列出来）时，调度员没给提问就补一个，交给 search agent 查着推荐，推荐完的几座列成按钮（v0.7.1 的 `_offer_parks`）。trace 记 `park_kind_ask`。`tests/test_dispatcher.py` 加了一条（不改代码时失败）。
- 没改提示词：改调度员的提示词要换版本、所有录音重录；这里用代码兜底，和 v0.7.1 的换公园一样。
- 验证：Copilot 540 个测试、十一组回放门禁（这条规则没有碰到任何已有考题的录音）、ruff 都过。这句话没有进 live-v1（那一批冻结了，修过的也不算没见过的），下次加考题时放进去。
- 还看到的：search agent 回答“这个季节有什么推荐的”用了 34 秒、第 5 句 21 秒（几步查资料，每步调一次 Gemini），没在这次改。
- 演示前再真跑 live-v1 的时间改成 12 月 3 日前后（仓库主人 11-25 定的，到时候先问）。
