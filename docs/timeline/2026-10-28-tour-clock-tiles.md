# 10-28：路线讲解改成“一个钟说了算”，地图提前下载、拉远（分支 `feature/tour-scrub-alltrails`）

- 为什么做：仓库主人说地图渲染太慢（车开过去了地图还没出来，太远的行程可以不用放大太多），进度条没能跟着视频进度变化，想要 YouTube 那样能拖的进度条（O83、O84）。找了现成的方案：HyperFrames、Remotion 这类做视频的框架是同一个思路（每一帧都按时间算出来），但它们是生成视频文件的，驱动不了实时的 MapLibre 地图和朗读，所以照这个思路自己改。
- 原来的动画是“一件事做完再做下一件”（车开到站、念完、再走），进度条是反过来从状态推算的：念话的实际快慢和估计的不一样时，进度条停住或跳一截，拖动也只能跳到一段的开头。现在整段动画是一条时间线，`state.position` 是播到第几毫秒，每帧钟往前走、再按这个时间摆出画面；讲解词按每句的阅读时间排在时间线上，一句念得比估计的慢，钟在下一句开始前等它。拖动进度条画面跟着手走，松手从那一句接着念；提示里写哪一段、几分几秒；J / L 跳 10 秒。
- 朗读快慢：浏览器试的时候发现 Windows 自带的中文声音比阅读时间慢两三成，进度条三天两头停下来等。改成边念边量，最近几句的中位数和时间线用的差一成以上就重排时间线（总时长从 8:57 变成 10:47），记在这台设备上。浏览器说了念却一直没开口的（Claude 的内置浏览器就是），原来要等估计时间的 2.5 倍再加 2 秒，现在 1.2 秒还没开口就按阅读时间只出字幕，也不拿来量快慢。
- 地图：每天开始前沿路线按跟车镜头的缩放提前下载瓦片（`src/lib/offline-maps.ts` 的 `tilesAlongPath`，浏览器里看过，地图再要这些瓦片时直接从缓存拿，3–8 毫秒）；长途时镜头拉远（9.6 级，原来 10.2）；讲解版的 3D 地形改用 512 像素的地形源（`tour-dem`）；播放时镜头压低远处少下载；底图跟不上时车慢下来等。一开始按 `areTilesLoaded()` 判断，地形阴影、远处的瓦片总有几块在下载，车有一半时间在慢，改成只看底图和 3D 地形，每段开车最多为它慢 4 秒。
- 顺带：只开车换住处的一天讲解不再说“今天去 0 个地方”（10-28 修引擎时把皇家岛的渡轮挪到了第二天，第一天成了只开车的一天）。
- 检查：`tests/route-tour.test.ts` 加了时间线定位、开车距离、讲解从哪句念起的测试，`tests/offline-maps.test.ts` 测沿路线取瓦片。浏览器里（皇家岛 + 航海家 5 天）：平常版进度条一秒走一秒、第 1 天到第 2 天换得对；讲解版拖到一半跳到第 2 站、从那句讲解念起；J / L、左右键、空格都对上了（每一次跳过去，牌子、第几天、念到第几句都对）。后半段 Claude 的窗口不在前面，内置浏览器降到一秒一帧，播放的快慢没法再量，请仓库主人自己看一遍。
