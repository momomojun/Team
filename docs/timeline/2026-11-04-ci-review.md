# 11-04：CI 加 Ruff 和评测成绩评论、CodeRabbit 审代码、scrum 周报草稿（分支 `feature/ci-review`）

- 为什么做：仓库主人 11-02 定了按课程大纲补 LLMOps 的几块，第一步是代码审查和 CI（GOALS P27、P28、A7）；朋友推荐了 CodeRabbit。
- CI（`.github/workflows/ci.yml`、`release.yml`）：
  - Copilot 那一项先跑 `ruff check copilot`（配置在 `copilot/pyproject.toml`：只查真 bug——语法、没定义的名字、没用到的变量、循环里的闭包、字符串里的控制字符，不管风格）；
  - 八组回放门禁前一组没过也接着跑，成绩才是全的（有一组没过照样失败）；
  - 跑完用 `copilot/eval/pr_summary.py` 把八组成绩整理成一张表，写进 CI 的摘要页，PR 上贴一条评论、每次推送更新同一条。
- Ruff 第一次跑就查出两处真 bug：`pipeline.py`、`qa.py` 的正则里本该是 `\b`，写进去的是退格字符，回答问题时一直拿不到出行日期、英文追问的代词认不出。修好以后用 `conversation.py --fill`（新加的，只补录录音里缺的调用）补了 30 次本机模型调用，多轮对话 v2 从 14/15 组到 15/15 组，基线抬高；其余七组不变（RESULTS.md 最后一节）。另外改了几处小的：循环变量和 import 重名、没用到的变量、补录时 Windows 上混进 CRLF。
- CodeRabbit（`.coderabbit.yaml`）：用简体中文审，跳过自动生成的数据、评测录音和锁文件，按目录给重点（Copilot 看编造、真调 API、key；数据看来源和核对日期），把 AGENTS.md、GUIDE、DEVELOPMENT、COPILOT、ENGLISH 当规矩。只提意见，不是必需的检查。要仓库主人在 coderabbit.ai 装 GitHub App 才生效。
- scrum 周报草稿：`npm run scrum`（`scripts/scrum-week.mjs`）把这一周的时间线、按人分的合并 PR 和 GOALS 里还没完成的整理到 `docs/scrum/<日期>.md`，“下周计划”“卡住的”人来填。第一份是 `docs/scrum/2026-10-29.md`。
- 检查：`ruff check copilot` 通过，pytest 445 个全过，八组门禁全过。
