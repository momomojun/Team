# 11-20：每晚读公告只维护一个 issue、一个分支；清一次积压，之后每周处理（分支 `chore/alerts-rolling-issue`）

- 为什么做：每晚读 NPS 公告的工作流，10 月 20 日以后每晚开一个新 issue、推一个新的 `bot/closures-<日期>` 分支，没人看：到 11-20 堆了 26 个 `nps-alerts` issue、22 个分支，营地对照和数据保质期也有 5 个开着。网站和 Copilot 排两周内出发的行程用的是每晚自动发布的关闭清单（`data/alerts-live`），不受影响；受影响的是人工核对的 `closures.ts` 越来越旧、issue 太多看不过来。仓库主人定：机器只维护一个 issue，先清一次积压，之后每周集中处理一次。
