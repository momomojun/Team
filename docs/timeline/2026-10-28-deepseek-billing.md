# 10-28：接 DeepSeek、所有模型的计费总账、OpenRouter 换免费模型（分支 `feature/deepseek`）

- 为什么做：仓库主人申请了 DeepSeek 的 key 想试一下（O86）；要后台给所有模型计费，免费档的 API 在各家后台看不到用了多少（O87）；OpenRouter 上的 MiniMax M3.1 Flash 不再免费，要找免费能用的（O88）。
- DeepSeek（`providers.DeepSeekProvider`，`COPILOT_PROVIDER=deepseek`，key 写在 `.env.local` 的 `DEEPSEEK_API_KEY`）：接口和 OpenAI 一样（api.deepseek.com），型号 `deepseek-flash`（V4.1 Flash）/ `deepseek-v4-pro`。只认 JSON 模式，不认 JSON Schema，schema 写进系统提示词（官方要求提示词里有“json”这个词）；思考模式默认开，聊天时关掉，`COPILOT_REASONING=low / high / max` 打开；回空内容（官方说偶尔会）当成出错交给下一家，余额不够是 402 不重试。全套六组评测 268 次花了 $0.08（按白天高峰价算的上限）：单句不如 Gemini（没见过的 40 句 34 对 39），多轮、真实对话差不多（v3 15/15）。成绩在 RESULTS.md 第五轮。仓库主人看了成绩定的：放在免费的三家后面、本机模型前面当付费备用（聊天和读公告两条链都是，O89）；线上要另加 `DEEPSEEK_API_KEY` secret 才会用。
- 计费总账（`nps_copilot/ledger.py`）：每一家真的调用模型、拿到回答的地方都过 `providers._billed` 记一行（回放录音、测试的假模型不记），写明谁调用的（`COPILOT_SOURCE`：聊天、读公告、评测、裁判，各入口启动时设）、哪个型号、token（没回报的按字数估、标 estimated）、多久。按天、按进程各一个文件：一开始两个评测同时跑往同一个文件追加，Windows 上两行搅在一起，改成文件名带进程号、读的时候跳过坏行。`monitor.billing` 算实际花费（`PRICES`）和按付费标价折算（`LIST_PRICES`，各家官网 10-28 的价：Gemini 3.5 Flash-Lite $0.30 / $2.50、Groq Qwen3.8 27B $0.80 / $4.00……），`FREE_LIMITS` 是免费档每天的上限（OpenRouter 免费模型合计约 50 次、Groq 每个模型 1000 次和 20 万 token、Gemini 500 次）。每晚 GitHub 上读公告的那一份由 `copilot/scripts/publish_usage.py` 并进 data/alerts-live 分支的 `usage.json`；后台（`/api/copilot/admin`）把它和本机服务 `/stats` 的 `billing` 加起来，新的一块“计费（所有模型）”：调用、实际花费、按标价算、按模型和来源的表、今天的免费额度用了几成。命令行 `python -m nps_copilot billing`。
